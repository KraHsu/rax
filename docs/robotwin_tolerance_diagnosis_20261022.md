# RoboTwin 容差验证：原因定位与修复

这次修复针对验证方法和专家后续轨迹，使用 clean `adjust_bottle`，不涉及 OpenWAM 训练后的成功率。上一轮 514 次实验保留为原始证据；其中的指令跟踪区间不再解释为物理可行区间。

**最终 12 对同抓取状态复测：冻结后续轨迹成功 6/12；保持原姿态、补偿后续位置后成功 12/12，且均通过额外 0.5 秒保持检查，无规划失败。** 本轮共新增 168 次执行，5 个新环境初始化的 20 个前后基线全部成功；29 项相关代码测试通过。

## 1. 向下请求 40 mm，实际没有向下 40 mm

seed 0 的诊断中，抓取目标 Z 为 0.855540 m，实际末端约 0.895914 m，差 40.374 mm。下降结束时 `fl_link8` 与 `table` 有约 0.747 N·s 接触冲量；`fl_joint2` 的实际位置与驱动目标差约 0.089 rad。闭合后两根手指仍与桌面接触。

因此，末端被桌面阻挡，而不是动作解码把 −40 mm 当成了别的单位或坐标。它随后仍可抓住瓶子，但这不能验证 −40 mm 请求位置可行。

修复：统计区分请求位置、真实位置和任务结果。成功执行保留**真实位置样本**，不把请求值写成物理允许范围，也不因跟踪偏差而把真实成功点一起丢掉。数据出口是 `measured_feasible_samples`。

同样修正了“向上容差为零”的错误解释。请求上移 20 mm 的两次成功 adaptive 重复中，抓取结束的实际 Z 偏移为：

| clean seed | 实际成功偏移样本（mm） |
| --- | --- |
| 0 | 19.400、19.815 |
| 1 | 18.721、18.667 |
| 2 | 16.853、16.858 |

这些是真实执行的成功点，不是已证明连续区间的上下界。闭合阈值事件位置与抓取结束位置是不同特征，映射训练标注时必须使用同一种特征。

## 2. 组合失败包含冻结后续目标造成的伪边界

原生专家先抓取，再沿末端局部轴抬升，最后根据当时瓶子与末端的相对位姿计算摆正目标。旧扫描只偏移抓取目标，却冻结了之后的末端目标，因而改变了专家的执行关系。

seed 0 的 `grasp_x=32.5 mm, grasp_y=-15 mm` 在旧试验 74 中正确执行抓取、带动物体抬升，但最后瓶子功能点高度只有 0.899609 m。官方成功阈值是严格大于 0.9 m。这里既有接触造成的瓶子相对抓取位置变化，也有后续末端目标没有补偿该变化的问题。

新增实验把一个抓取后的 PhysX 状态、关节驱动目标、夹爪指令和测量序列保存下来，再分别执行不同后续轨迹。分叉恢复检查末端、瓶子和关节状态；这样两种后续轨迹共享同一次抓取。

最初 6 对同状态对照结果：冻结后续轨迹 2/6 成功；原生专家重新计算后续轨迹 5/6 成功，另 1 次规划失败。4 个冻结轨迹任务失败都被重新计算后续目标修复。典型失败中，瓶子相对末端的位置在抬升、搬运间保持稳定，刚性关系预测最终瓶子位置的误差只有 0.259 mm；这直接支持“末端终点与改变后的抓取关系不匹配”的原因。

为了避免原生自动朝向选择重新引入规划失败，进一步实现了只补偿位置的后续轨迹。设参考抓取后瓶子功能点在末端坐标系中的位置为 `r_ref`，本次为 `r_now`，原末端目标为 `(R, p)`：

```
p_corrected = p + R @ (r_ref - r_now)
R_corrected = R
```

在物体保持相对抓取位置的条件下，两种抓取到达相同的物体目标位置。原末端朝向和抬升目标保留，末端后续目标位置按实际抓取关系调整。实现为 `retarget_position`，并有旋转坐标系下物体目标不变的回归测试。

最终独立初始化运行 `diagnosis_seed0_retarget` 中，12 对抓取动作及其测量记录逐项一致，分叉来源 trial id 一一匹配。冻结轨迹结束时瓶子功能点高度为 0.865115–0.910728 m，补偿后为 0.961561–0.962978 m；额外保持 0.5 秒后为 0.962465–0.964569 m。冻结轨迹失败 trial 为 5、7、9、11、13、25，对应补偿分叉全部成功。该结果解决了这个组合样例的后续目标失配，尚不代表跨任务或训练策略成功率。

此处使用物体位姿是**离线仿真校准**的一部分；训练损失仍只使用解码动作和数据中记录的几何约束。该方法验证带有指定后续轨迹的抓取，不直接认证原来冻结的整个 action chunk。

## 3. Y +65 mm 的重复失败是真实抓空边界

同状态 6 对试验中，冻结和重新计算后续轨迹均为 4/6 成功，2 对共同失败。失败时瓶子已经被推离夹爪；闭合结束没有手指—瓶子接触，瓶子仍与桌面接触，随后没有跟随末端抬升。

这不是后续终点补偿可以修复的情况。这个点不能纳入稳健的允许区域。校准中保留它作为失败样本，并要求用组合实验检验候选边界，不将单轴最大值直接组成一个长方体。

## 实现与复用

- `scripts/diagnose_robotwin_tolerances.py`：逐动作记录真实关节位置、驱动目标、真实夹爪关节开度、接触冲量和瓶子位姿；支持同抓取状态分叉。
- `services/robotwin/tolerance.py`：请求跟踪与真实可行样本分离；位置补偿函数。
- `scripts/summarize_robotwin_diagnosis.py`：配对结果、刚性抓取关系检查和真实成功样本。
- `scripts/summarize_robotwin_tolerances.py`：旧实验同样输出真实成功点，保留原始指令空间扫描记录。
- RAX 几何约束模板：明确后续轨迹条件、坐标/单位、事件特征映射、联合试验证据，禁止把指令偏移或不同后续轨迹混成同一个允许区域。

重跑命令（在 H200 的原生 RoboTwin 环境中）：

```bash
ROBOTWIN_PATH=/mnt/data/liangjiaqi/RoboTwin CUDA_VISIBLE_DEVICES=0 \
/mnt/data/liangjiaqi/yzm/miniconda3/envs/RoboTwin/bin/python \
  scripts/diagnose_robotwin_tolerances.py \
  --manifest /mnt/data/liangjiaqi/rax_train/manifests/adjust_bottle_pilot.json \
  --program-from /mnt/data/liangjiaqi/rax_train/validation/tolerance_seed0_v2 \
  --cases-json /mnt/data/liangjiaqi/rax_train/validation/diagnostic_retarget_cases.json \
  --output /mnt/data/liangjiaqi/rax_train/validation/NEW_RUN \
  --repeats 12 --continuations object_position
```

原始数据位于 H200 `/mnt/data/liangjiaqi/rax_train/validation/diagnosis_seed*`，本机分析副本位于 `runtime/tolerance_study/diagnosis/`。原始专家 HDF5 的参考包络仍属于示范先验；不能把此次某一种后续轨迹下的宽抓取样本，直接与另一种抓取的窄终点包络拼成训练标签。
