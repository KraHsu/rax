# Fixed-reference branch admission for native development

This opt-in collector mode adds `--branch-spec` for ten original active template branches of stack_bowls_two, place_bread_basket, place_mouse_pad, stack_bowls_three and put_bottles_dustbin. Default nonbranch collection is unchanged. It does not change the compiled constraint schema, OpenWAM loss, dataset, registry status or training/publication gates.

The specification binds the literal native task, branch, exact original template hash and active registry entry, native task source hash, and finite seed interval. Each branch has three target distinct non-training reference scenes, at most thirty capture slots, and two conditional baselines plus the existing eighteen cases per scene. Sibling active branches use starts10000/10100/10200. Candidate branches and the unobserved dustbin left3/right0 branch are not admitted.

Complete numeric reference arrays are validated and both arms must have equal length, finite unit WXYZ poses and [0,1] gripper values. Threshold events are recomputed from those arrays, including exact-.5 crossings. Neither caller event arrays nor instruction arm metadata can override them. Mouse subjects use initial actor side plus reference arm. Bread saved `{a}` is not authoritative. Dustbin uses fixed reference left3/right1 or2 cycles; initial right count remains diagnostic because native selects each pickup arm using the bottle's then-current X. Other unreviewed static/reference mismatches are retained as unsupported references.

Admission occurs before template instantiation. Every branch capture saves its initial scene and all collected samples; a completed but wrong-branch expert capture also saves the full reference payload. Such branch rejection or ordinary unsuccessful reference generation consumes a slot within the predeclared thirty-slot scan. Native cleanup failure, source/template drift, malformed reference or hash failure is an infrastructure error and stops immediately. No malformed identity is handled by choosing another seed.

After a successful reference file is written, a separate immutable sidecar binds its actual bytes SHA256, full frame count T, T-1 action frames, scene/content hashes, recomputed events, exact branch selection, spec hash and guard policy/source fingerprint. There is no self-referential file hash. Manifest entries bind both files. Plan validation and each trial before native initialization re-read the complete arrays, recompute the sidecar and recompile the frozen template's constraints. Byte hashes are exact; derived compiler arithmetic uses the existing acceptance comparison tolerance.

A branch run cannot resume an existing run state. Production owners additionally require a new branch package root, one-shot intent and absent output. A failed baseline stops the entire branch; no later baseline, intervention, scene replacement or retry follows. The other previously captured references remain evidence but are not executed after that failure. Independent branch queue entries may proceed only according to their separately frozen finite plan.

CPU fixtures synthesize EEF trajectories and preregistered seeds around source-checked initial scenes/event schedules. They test the API and tamper rejection, not successful native physics. Native development completion is not formal acceptance, holdout success or permission to activate candidates. Full source-domain gaps remain documented in the branch applicability report.
